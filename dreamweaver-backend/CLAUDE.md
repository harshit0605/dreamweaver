# CLAUDE.md — dreamweaver-backend

FastAPI media execution service on **:8001**. Python 3.12, `uv`.

Deliberately dumb: it takes a prompt plus references and returns media URLs. No storyboard state, no database, no orchestration — that all lives in the Next.js BFF. Keep it that way.

```bash
uv sync
uv run uvicorn main:app --reload --port 8001
```

Needs `.env` (see `config/settings.py`). Its README says port 8000; `.claude/launch.json` and both launcher scripts use **8001** — that's what the frontend's `NEXT_PUBLIC_API_URL` expects.

---

## No test suite here

`scripts/test_*.py` are **manual scripts that hit live provider APIs** and dump artifacts into `test_outputs/`. They are not pytest, there's no pytest config, and running them costs real API calls.

Don't run them as verification, and never report them as "tests passing." Verify changes here by exercising the endpoint.

## Adding a model — both steps, or it 404s

**1. Catalog it** in `config/models.py`:

```python
ModelConfig(
    id="...", name="...", provider=ModelProvider.MODAL,
    capabilities=[ModelCapability.IMAGE_GEN, ModelCapability.HD],
    description="...", enabled=True,
)
```

`ModelCapability` covers `image_gen`, `image_edit`, `video_gen`, `video_edit`, `camera_control`, `audio`, `hd`, `4k`, `fast`, `inpainting`, `outpainting`. Only `enabled=True` models are returned by `/api/models`.

**2. Make a provider claim it.** `ProviderRegistry` builds its `model_id → provider` map from each provider's `supported_models` at registration. A model in the catalog that no registered provider lists resolves to `ProviderError(MODEL_NOT_FOUND)`.

Currently registered in `initialize_providers()`: `OpenAIImageProvider`, `ModalImageProvider`. Video providers exist under `providers/modal/video.py` and `providers/google/video.py` — check whether yours is actually registered before assuming it's reachable.

Catalog today: `gpt-image-1`, `dall-e-3`, `dall-e-2`, `zennah-image-gen`, `zennah-qwen-edit`, `zennah-qwen-multiview`, `ltx-2.3`, `ltx-2`, `veo-3.1`, `sora-2`.

## Adding a provider

Subclass `ImageProvider` / `VideoProvider` from `providers/base.py`: set `provider_name` and `supported_models`, implement the abstract methods, call `validate_request()` on entry, and raise `ProviderError(message, provider, error_code)` — never a bare exception, the API layer maps these to responses. Register it in `initialize_providers()`.

## Gotchas

- **CORS is a hardcoded list** in `main.py` — localhost 3000–3005 plus one Vercel host. A frontend on a new port needs an entry.
- **The origin list is duplicated**: once in the `lifespan` debug print, once in the middleware. They've already drifted (the print omits 3002–3005). Update the middleware; that's the one that matters.
- `settings.py` reads `.env` via pydantic-settings; keys are optional and default to `None`, so a missing key fails at call time, not at boot.
- Upload/S3 config (`UPLOAD_API_*`, `S3_BUCKET`, `S3_REGION`) is what turns generated bytes into URLs the frontend can persist.

## Style

- Providers raise `ProviderError` with an `error_code`; the API layer translates. Don't leak provider SDK exceptions upward.
- Requests and responses are Pydantic models in `providers/base.py` — extend those rather than passing dicts.
- Keep this service stateless. If a change needs storyboard context, the context belongs in the request body, assembled by the caller.
